## modem@sms — LTE/NR SMS Management
Manage LTE/NR modem SMS service.

### Configuration ( `modem@sms` )
**modem@sms** is the SMS service bound to the first LTE modem.
**modem@sms2** is the SMS service bound to the second LTE modem.

```json
// Attributes introduction 
{
    // Enable or disable SMS-to-command handling.
    // "enable" means incoming SMS can be parsed as HE command.
    "he":"enable or disable the he command",                  // [ "disable", "enable" ]

    // Optional sender whitelist for HE command.
    // Multiple patterns are separated by ';', and each pattern is matched by substring.
    "he_contact":"set a contact to send the he command",      // [ string ]

    // Optional command prefix required in SMS body before HE command text.
    // If configured, messages without this prefix are ignored.
    "he_prefix":"set a prefix at the he command"              // [ string ]
}
```

Example, show all the configure
```shell
modem@sms
{
    "he":"enable",                                         # enable SMS-to-command feature
    "he_contact":"17688704240;10000;+8617688704240",       # only accept commands from these phone numbers (substring match)
    "he_prefix":"CMD:"                                     # SMS content must start with "CMD:" to be processed as a command
}
```

> **Security Warning**: When enabling the `he` feature, it is strongly recommended to configure `he_contact` to restrict which phone numbers can execute commands. Without this restriction, any incoming SMS could potentially execute system commands.

#### SMS-to-Command (HE) Feature
When `he` is set to `enable`, incoming SMS messages can be interpreted as system commands and executed. The execution results are automatically replied to the sender via SMS.

**Character Conversion Rules**:

Since some special characters may be difficult to input or transmit via SMS, the following character conversions are performed:

| SMS Character | Converted To | Meaning |
|--------------|--------------|---------|
| `>` or `O` | `@` | Object separator |
| `!` or `F` | `.` | Attribute separator |
| `?` or `A` | `:` | Method call |
| `%` or `U` | `/` | Path separator |
| `G` | `=` | Assignment |
| `R` | `\|` | Pipe |
| `(`, `{`, `S` | `[` | Parameter start |
| `)`, `}`, `E` | `]` | Parameter end |

**Example**: Send command via SMS
```
# Original command: land@machine.restart[5]
# SMS input: landOmachineFrestartS5E
# Or: land>machine!restart{5}
```

**HE Command Execution Flow**:
1. SMS is received and stored in the incoming directory
2. If `he` is enabled, the SMS content is checked
3. If `he_contact` is configured, the sender number must match (substring match)
4. If `he_prefix` is configured, the SMS content must start with this prefix
5. Characters are converted according to the conversion rules
6. The command is executed as a HE system command
7. The execution result is sent back to the sender via SMS

**Note**: UCS-2 encoded SMS messages are not processed as HE commands.

### Component API
**Directly callable** APIs from HE / eline / HTTP `/he`.
**modem@sms** is the first LTE modem SMS service.   
**modem@sms2** is the second LTE modem SMS service.


+ `send[ contact, content ]` **send an SMS**
    - contact ----------- [ string ], destination phone number
    - content ----------- [ string ], SMS text content
    - invalid parameters or send command failure: return tfalse
    - request accepted: return ttrue
    - this API is a fire-and-forget send request; delivery receipt is not guaranteed by this return value
    
    Example: send "i miss you" to 17688704240
    ```shell
    modem@sms.send[ 8617688704240, i\ miss\ you ]
    ttrue
    ```

+ `action[ event, file ]` **SMS event handling (internal use)**
    - This API is used internally by the SMS daemon to process received SMS
    - When `he` is enabled, incoming SMS triggers this API to execute HE commands
    - The execution result is automatically sent back to the sender via SMS
    - **Note**: This API is not intended for manual invocation

#### SMS Storage
SMS messages are stored in the following directories:

| Directory | Purpose |
|-----------|---------|
| `{var}/modem@sms.sent/` | Successfully sent SMS |
| `{var}/modem@sms.failed/` | Failed to send SMS |
| `{var}/modem@sms.checked/` | Checked SMS |
| `{var}/modem@sms.outgoing/` | Outgoing SMS queue |
| `{internal}/modem@sms.incoming/` | Received SMS (queried by `list[]`) |

#### Encoding Support
- **GSM 7-bit**: Standard SMS encoding
- **UCS-2**: Unicode encoding for non-ASCII characters (e.g., Chinese). Automatically converted to UTF-8 when listing
- **Binary**: Binary SMS content is not processed as HE commands

#### Dependencies
The SMS service relies on the following external components:

- `smsd` - SMS daemon process for low-level SMS handling
- `sendsms.sh` - Script for sending SMS
- `iconv` - Character encoding conversion utility

#### Complete Configuration Example
```json
{
    "he": "enable",
    "he_contact": "17688704240;10000;+8617688704240",
    "he_prefix": "CMD:"
}
```

**Explanation**:
- `he`: Enable SMS-to-command feature
- `he_contact`: Only SMS from numbers containing "17688704240", "10000", or "+8617688704240" will be processed as commands (substring match)
- `he_prefix`: SMS content must start with "CMD:" to be processed as a command

**Example SMS for HE command**:
```
CMD:landOmachineFstatus
```
This will execute `land@machine.status` and reply with the result.

### Lifecycle API
+ `setup[]` / `shut[]` — driven by **`usbdrv@…`** / modem driver registration; **not** listed in the default modem package **`init`** table.
+ Consult modem driver component docs (**`modem@ec2x`**, **`modem@rm500u`**, …) for bring-up.


### C Code Example
**Read and update configuration**

```c
#include "skin/skin.h"

static int example_config_modem_sms(void)
{
    char buf[128];
    if (sgets_string(buf, sizeof(buf), "modem@sms", "status") == NULL)
        return -1;
    return ssets_string("modem@sms", "enable", "status") ? 0 : -1;
}
```

**Call component methods**

```c
#include "skin/skin.h"

static void print_call_error(const char *api, talk_t ret)
{
    if (ret == tfalse || ret == terror || ret == tpanic)
        printf("%s failed, errno=%d\n", api, errno);
}
```
